## 1. Executive decision for BA01 + BA02

**Recommend Phase A first: a deterministic, allowlist-only, redacted GitHub job summary; no raw trace or screenshot artifact.** Use built-in \`GITHUB_STEP_SUMMARY\` in a separately approved future implementation. Optionally include a manifest hashing **sanitized output only**. The smallest useful evidence is an exact run/attempt/SHA plus a *safe category* of failing spec/line and bounded, enum-only expected/actual, with missing evidence explicitly \`NOT AVAILABLE\`.

**Defer Phase B (failure-only uploaded artifact)** until the owner approves public exposure, GitHub storage budget, an independently reviewed sanitizer and negative canary tests. Do not treat a regex replace on a ZIP, screenshot, DOM snapshot, network trace or error-context Markdown as proof of safety. **Default no upload; deny on any uncertain field.** A 3-day, <=1 MiB sanitized *text-only* artifact is a proposal, not a current setting or permission. Full browser trace/image publication should remain prohibited without a separate design and verification.

**Why:** GitHub's trace viewer can display DOM snapshots, screenshots, request metadata, request/response bodies, console and source. Those can disclose creator captions, Vietnamese narration/transcripts, input values, authorization headers, URLs or private assets. Hashing a raw artifact does not sanitize its content and may still expose predictable low-entropy values. Public repository artifacts must be treated as externally readable by parties with repository read access; don't rely on obscure URLs or short retention as an access-control boundary.

## 3. Threat model and trust boundaries

| Surface | Potential disclosure/abuse | Minimum countermeasure |
| --- | --- | --- |
| Public CI run page, summary, and artifact downloads | Job summary is viewable to readers; a public-repo artifact must be presumed exposed to readers/authorized downloads/API. | Publish only constant keys and allowlisted non-sensitive fields; never place raw error strings, DOM or network blobs in summary. |
| DOM, input fields, snapshots and screenshots | Personal input, captions, transcript, story prompt, tokens displayed on page, images or creator assets. | **Never upload raw Playwright test-results.** No image/screenshot artifact in Phase A; optional Phase B excludes pixels unless independently proven sanitized. |
| Network requests and responses | URLs/query strings, cookies, bearer headers, bodies, private API endpoints, storage identifiers. | Never publish raw HAR/trace/network, HTTP headers, request bodies, absolute paths or query parameters. Prefer typed status/error-category from safe structured test result. |
| Exception/stack and file names | User-controlled messages, private filesystem paths, data embedded into test title. | Fixed known repository-relative spec ID from an explicit lookup table; numeric line within repository spec; fixed-category errors. Truncate and replace unknown values with \`[REDACTED]\`. |
| External PR/fork source and metadata | Malicious branch name, PR title, assertions or failing-output text used as shell/Markdown injection; untrusted build code. | Do not interpolate untrusted contexts in shell or execute arbitrary trace content; no \`pull_request_target\` with PR head checkout; least-privilege \`contents: read\`; approvals for any privileges. |
| CI action supply chain | Mutable action tags, compromised transitive dependencies or third-party uploads. | Prefer built-in \`GITHUB_STEP_SUMMARY\` and already installed tooling; any future upload action requires reviewed origin/license, **immutable commit SHA pin**, security review and explicit owner approval. |
| Storage / availability | Overage charges, unusually large artifacts, default long retention, leakage during public exposure. | No artifact Phase A; Phase B requires verified account-level budget and stop-cap, bounded bytes, max one safe text artifact/failing run, retention 3 days and lifecycle verification. |
| Sanitizer logic / logs | Secret may remain in screenshot pixels/compressed ZIP, filename, sanitizer exception or upload log. | **Fail closed**: no upload on unknown encoding/type/size/redaction result; generic \`EVIDENCE_UNAVAILABLE\` notice (no raw exception). Original test still fails. |

**What is NOT a sufficient sanitizer:** renaming ZIP, masking tokens with a few regexes, excluding request headers alone, replacing display text while preserving raw screenshot pixels or DOM attributes, deleting files *after* upload, or showing SHA-256 of raw private data in a public summary. Canary fixtures are **synthetic and inert**; never use real credentials or production creator content.

## 4. FREE-first alternatives and evaluation

| Option | Safety and utility | Cost/license state | Decision |
| --- | --- | --- | --- |
| **A0: status/run links only, no artifact** | Already possible using native GitHub workflow run pages; very safe but poor reproduction details when failing trace evaporates. | **FREE VERIFIED** for standard GitHub-hosted runner usage on public repo; real account spend/billing state **NOT VERIFIED**. | Baseline. |
| **A1: allowlist-only \`GITHUB_STEP_SUMMARY\`** | Exact SHA, run URL/attempt, fixed spec ID and line, error class, redacted expected/actual enum, artifact status; no raw attachments. | **FREE WITH LIMITS**: native GitHub Actions feature; summary/log retention and account-level policy may apply. No new dependency or storage artifact in proposal. | **ADOPT only after separate implementation approval.** |
| **A1b: safe text hash manifest** | Deterministic SHA-256 + byte length for sanitized summary generated **after allowlist validation**; helps compare repeated failures, not a security proof. | **FREE VERIFIED** with standard built-in hashing functionality; account/compute usage still subject to platform limits. | Optional inside Phase A; no hash of secret, token, raw trace or private prompt. |
| **B: approval-gated sanitized failure-only artifact** | More evidence if an audited sanitizer preserves only safe text/metadata; explicit artifact absence is acceptable. | **FREE WITH LIMITS**: GitHub Actions artifact storage has included quota, retention and possible overage; GitHub account usage, plans, budgets and permissions **NOT VERIFIED**. \`actions/upload-artifact\` is an external repository action, not approved or pinned here. | **DEFER** pending owner, security, license/source, actual storage and fixture acceptance. |
| Raw screenshot, ZIP trace, unredacted HAR or \`test-results\` upload | High reproduction value but unacceptable public leakage risk. | Storage and publication risk, not free-by-default just because runner is public. | **REJECT**. |

GitHub documents that **standard GitHub-hosted runner compute for public repositories is free**, while storage has separate included allowances, policies and potential charges; larger runners are chargeable. No account-level remaining quota, billing method, storage cap or owner budget has been inspected. GitHub UI artifact download requires sign-in/read access; GitHub REST artifact metadata may be readable for public resources. Assume public exposure; **short retention is not anonymization**.

## 5. Proposed Phase A implementation contract — NO implementation now

**Future exclusive proposed paths, only after BA approval and independent ownership check:** \`.github/workflows/ci.yml\` (one minimal summary step), plus optionally one **new** isolated safe-result formatter/test file if BA allocates it. No change to watcher \`.github/workflows/t01-pr-qa-watch.yml\`, product code, Playwright behavior/assertions, artifact service, or GitHub permissions by this research PR.

On a future intentional failing Playwright fixture, the summary should use only an allowlisted typed record similar to:

~~~text
CI_EVIDENCE_SCHEMA=1
COMMIT_SHA=<40 lowercase hex, validated against checkout SHA>
RUN=<numeric run_id> ATTEMPT=<numeric run_attempt>
WORKFLOW=Whiteboard Studio CI
SPEC=studio_focus_visible  LINE=114
ERROR_CLASS=ASSERTION_MISMATCH
EXPECTED=VISIBLE_FOCUS  ACTUAL=NO_VISIBLE_FOCUS
TRACE_PUBLIC_ARTIFACT=NOT AVAILABLE
SOURCE=GitHub Actions run link (repository/owner allowlisted)
~~~

Values above are **illustrative inert data, not an observed future run**. Whitelist spec identifiers and error classes (never arbitrary test names, PR titles, free-form \`Error.message\` or \`github.event.*\`). For unknown messages/statuses, write \`[REDACTED]\` or \`EVIDENCE_UNAVAILABLE\`, not a raw excerpt. Do not include an absolute filesystem path, customer/asset ID, timestamp-derived credential, image or secret. Validate line number against permitted spec and bounded integer range. Escape Markdown metacharacters and prevent output from being interpreted as shell commands; ideally write summary via a constant-template file generator with typed args.

**Phase A acceptance cases, future CI only:**

1. Deliberate failing safe fixture: actual failing test produces the schema, exact HEAD/merge-ref, run ID/attempt, fixed failing spec+line, class and safe enum expected/actual, explicit \`NOT AVAILABLE\` for no public artifact; failing test result **stays FAIL**.
2. Passing fixture: short \`PASS / failure evidence NOT APPLICABLE\` only; no fabricated failing spec or artifact.
3. Malicious test title / branch / DOM canary: inject synthetic \`C04_CANARY_DO_NOT_PUBLISH_7K9Q\` in any untrusted field. No canary in summary, log generated by formatter or manifest; expected \`[REDACTED]\`.
4. Missing JSON/invalid UTF-8/path/truncated test result: fail closed to safe \`EVIDENCE_UNAVAILABLE\`, preserve failing exit and do not publish raw exception.
5. Compare hash/determinism for repeated safe events and validate schema fields with an independent T01/T02 review.

No CI job should run solely to generate this research document; these are future acceptance tests. No real canaries were injected in this research.

## 6. Proposed Phase B acceptance gate — separate approval required

**Eligibility is ALL-or-NOTHING:** BA01/BA02+owner approve public visibility, account quota and a stop-budget; QA reviewer approves sanitizer source and actual negative tests; action and transitive dependencies/license reviewed and pinned to immutable SHAs. In a future implementation, constrain upload to:

- Failure-only and **no artifact if sanitizer fails**; max **one** sanitized artifact per failed run, no raw files included or copied.
- **Only fixed-schema UTF-8 text** from sanitized validator, no screenshots, DOM snapshot, headers, network body, asset, audio, ZIP, TAR, source code or report directory; **max 1 MiB total** proposed (fail closed above bound).
- **\`retention-days: 3\` target** after repository/org policy verification; validate expiration and deletion, not assume deletion is immediate or exposure reversible.
- Only immutable SHA-pinned, source/license-checked upload implementation with minimal existing permissions; no PAT, no external API, no card-required tier or new cloud account.
- No upload on \`pull_request_target\` privileged context and never run attacker-controlled code with elevated secrets.

**Negative fixture matrix (future only):**

| Fixture | Injected data (inert synthetic only) | Required result |
| --- | --- | --- |
| N1 DOM secret | \`C04_CANARY_DOM_7K9Q\` in input value, DOM text and rendered area | No artifact or fail-closed safe artifact-free result; no canary in summary, logs, artifacts or byte/manifests. |
| N2 network secret | \`C04_CANARY_HTTP_7K9Q\` in test HTTP header, URL query and response body | Same: **zero published artifacts**, original test failure preserved; no secret in summaries/logs. |
| N3 malformed/binary payload | Unknown ZIP, PNG, oversized file or unknown schema/encoding | Reject upload; safe \`EVIDENCE_UNAVAILABLE\`, no raw path/hash/bytes output. |
| P1 known-safe synthetic case | Fixed enum-only failure metadata, no DOM/request/user content | Single bounded artifact **only after explicit Phase B approval**, verify digest, size, 3-day retention and accessible-read threat assumptions. |
| P2 passing test | Successful Playwright run | **No failure artifact**, no false failure summary. |

Check **the actual published archive contents and compressed bytes**, output names, error messages, upload logs and artifact URLs for canaries (the uploader must not run if N1/N2 fail). A sanitizer cannot safely inspect or redact opaque pixel content from raw screenshots using text matching alone: therefore Phase B is **text-only** unless a separate proven design is approved.
