# T01 + T02 — Real video perceptual QA test-case matrix (G9 / G10)

**Scope:** Vietnamese whiteboard, narrated short video, 12/30/45/60s, 9:16 and 16:9. **Source:** creator negative video feedback 2026-10-31, [G10 gate #36](https://github.com/qualife1291/Auto-Tool-Video/issues/36), [voice #101](https://github.com/qualife1291/Auto-Tool-Video/issues/101), [visual #102](https://github.com/qualife1291/Auto-Tool-Video/issues/102), [layout #103](https://github.com/qualife1291/Auto-Tool-Video/issues/103), [QA gap #104](https://github.com/qualife1291/Auto-Tool-Video/issues/104). This is the tester-owned companion to [qa-evidence-gates.md](qa-evidence-gates.md) and [video-quality-standard.md](video-quality-standard.md).

**Policy:** all testers must distinguish **technical QA PASS-CODE** from **G10 actual viewer/listener approval** and from **publishing authorization**. Passing codec/decode/PTS/loudness/unit tests, unique file SHA, or ASR score alone NEVER proves Vietnamese intelligibility, meaningful artwork, usable layout, scientific accuracy or human approval. These cases must be executed on actual bytes from the final requested rendering, not inferred from YAML/source/logs or static sample captions. A synthetic eSpeak/Pillow fixture can prove technical behavior, **never** approved final narrator/art/rights.

## 1. Test setup and evidence contract

1. Confirm latest canonical full SHA, PR author HEAD, PR merged checkout SHA, run and artifact ID, storyboard and input provenance. Retrieve **two individual actual MP4s** (portrait and landscape) for the **same project/content, scene sequence and revision**; calculate their SHA256 independently. Do not call a ZIP archive or GitHub HTML an MP4 playback link.
2. Verify both file codec, duration, output resolution and full audio/video decode under unchanged G7/G8/G9 rules. Record what is genuinely NOT RUN: optional skipped FullHD job, missing rights-approved voice, model/provider not executed, actual product UI export, creator review.
3. Perform complete, continuous normal-speed **1x playback AND listening for the full two files**, with notes at every scene boundary and any suspect timestamp. Then inspect scene start, midpoint and end, transitions, visual/caption areas at a real phone size (around 390px logical viewport), 1080×1920 and 1920×1080 as available. If tester lacks means to listen or play the real file, **mark human perceptual tests NOT RUN** instead of claiming PASS from extracted images, ffmpeg or creator feedback. Separately record actual human creator negative/positive feedback with provenance.
4. Check words against Vietnamese narration after an initial **blind/no-transcript listen**, then read script and replay uncertain phrases. Record actual listener native language and device. Counts based on Vietnamese whitespace-separated tokens are **syllable/tiếng rate proxies**, not linguistically segmented WPM, not an automatic intelligibility threshold.
5. For each case record: ID, type technical/perceptual/human, aspect, MP4 SHA, source/rights, device/player, human reviewer and date, full playback coverage, scene/timestamp, expected vs actual, screenshots/frame hashes or audio sample SHA, severity (CRITICAL/HIGH/MEDIUM/LOW), status PASS/FAIL/BLOCKED/NOT RUN/PENDING HUMAN REVIEW, bug URL, fix SHA and retest SHA. Preserve before/after artifacts; do not overwrite RED.

## 2. Mandatory test matrix (execute for BOTH aspects)

| Test ID / priority | Concrete action | PASS condition | FAIL / BLOCK / NOT RUN evidence |
| --- | --- | --- | --- |
| RV-01 P0 · Actual-file provenance | Open each individual MP4 by computed SHA; verify same project story, revision, 9:16 + 16:9 and source/rights; FFprobe/whole-file decode separately. | Both actual files and input/source chain recorded, expected technical formats met. | ZIP URL only, wrong prior run/SHA, no byte access => NOT RUN/BLOCKED; codec failures => FAIL. |
| RV-02 P0 · Full human playback | Watch and listen full exact 9:16 and 16:9 files at 1x, every scene and transition; list device/player and any timestamp. | Reviewer confirms full-file playback and captures all observed defects. | Only head/mid/tail thumbnails, GIF, metadata or logs without actual 1x => human NOT RUN (never PASS). |
| RV-03 P0 · Vietnamese speech intelligibility | First listen without transcript at 1x; identify exact words and dropped/mispronounced syllables, then compare to approved script with native-speaking listener/creator. | Clearly understood and correct words, tone, endings and appropriate child-audience clarity, documented listener and samples. | Owner reports fast/unclear words, phoneme errors, unnatural TTS => G10 FAIL; no independent listener => tester human listening NOT RUN. |
| RV-04 P1 · Narration pace/pauses | Measure raw/trimmed/retimed WAV duration, active speech, silence, per-cue token/tiếng rate; correlate with normal-speed listening, punctuation and scene duration. | Natural pacing and useful pauses verified by listener, no rushed/clipped utterance, each cue fits timeline. | Rushed, syllables clipped or cue overflow => FAIL; rate alone/atempo=0.92 alone cannot PASS or establish comprehension. |
| RV-05 P0 · Word/scene synchronization | Compare spoken phrase with shown object/action/text at each second, before/at/after cuts; test all head/tail syllables and caption entry. | Each phrase delivered in the correct scene, visual holds long enough to understand it, no misleading early/late event. | Missing/repeated speech, visual arrives after corresponding statement, abruptly cut ending => FAIL with timestamp. |
| RV-06 P0 · Semantic art alignment | For each cue, write **expected visible identifiable objects AND action/state** from storyboard, then watch actual frame evolution; compare water vapor/cloud/rain, wet cloth/wind/sun/drying, crossing/pedestrian, appliance scenes. | Object/action meaningful without relying solely on caption; story progression understandable and scientifically appropriate. | Generic triangle for cloud/rain, stoplight for zebra crossing/adult, rectangle for fridge/cooking, shirt without wet→dry stage => G10 FAIL. |
| RV-07 P0 · Repetitive uninformative geometry | Compare each scene's illustrative ROI after accounting for zoom/palette and titles; watch sequentially; use perceptual image similarity/geometry as **warning**, then human semantic judgment. | Reuse is justified by clear narrated continuity, with visible action or state change; each new cue's meaning is expressed. | Twelve different cues backed by same oval+rectangle, same icon only recolored/repositioned => FAIL; differing PNG SHA alone is not sufficient. |
| RV-08 P1 · Legitimate continuity positive control | Reuse the SAME shirt/character across wet and dry scenes, preserving identity and relationships but changing moisture, wind/evaporation cues and state over time. | Intentional recurring subject is allowed; human can see and describe the action/state changes. | A blanket rule requiring every scene's source image/hash to differ is a **false positive** and must NOT be adopted. |
| RV-09 P1 · Whiteboard reveal timing | Replay early/mid/late progress at 1x and inspect first seconds in 3s short scenes; correlate draw/reveal/hold with narration, verify meaningful silhouette appears before cue ends. | Subject becomes recognizable at a useful point, reveals not excessively rapid/repeated or so slow that cue ends before art. | Fast flashing/partial meaningless strokes, same unrecognized object redrawn every scene, all reveal time consumed before text can be read => FAIL. |
| RV-10 P0 · Subject scale and frame hierarchy | Evaluate board/full_frame switches, subject-to-canvas ratio, crop/focal/zoom and captions side by side in both aspects at phone size. | Key subject legible and stable; visual hierarchy, focal area and captions consistent unless storyboard justifies a deliberate cinematic change. | Tiny icon in huge blank page alternating with clipped overzoom version or obscured object/caption => FAIL. |
| RV-11 P0 · Vietnamese caption readability | Read every caption at normal 1x, check accent marks and punctuation, max useful line grouping, consistent placement and safe zones, no overlap with hero art/controls. | All words/diacritics fully visible and readable on phone and desktop, timing matches spoken segment. | Cropped accents/words, orphan/unreadable text, overlap, caption arriving after relevant scene => FAIL. |
| RV-12 P1 · Motion and continuity | Watch whole video and seek discontinuities near every cut; scan warnings/scene frames for flicker, freeze, white flash, frame skip, illegal cloth-physics jump and artificial zoom. | Transitions deliberate and understandable; same character/object identity preserved, no unsafe flash or unexplained geometry jump. | Visual semantic critical => FAIL despite 30fps PTS/FFmpeg PASS; automated near-repeat warning alone => human REVIEW NEEDED, not automatically FAIL for an intentional still. |
| RV-13 P0 · Facts, children, rights | Independently check statements vs approved references, pedestrian/safety advice and illustrative assumptions; record image/audio creation rights and consent. | Story scientifically/age appropriate, hazards not misleading, rights/disclosures documented on the actual assets. | Unsafe advice, factual reversal, unknown source/voice consent => BLOCK G10 until corrected/cleared. |
| RV-14 P0 · Aspect and native export parity | Verify actual final UI/native 1080×1920 and 1920×1080 output for same source and story, not substituted low-res synthetic previews; compare every scene for crop, subtitles, audio packet/phrase identity. | Both true final-aspect exports validated, hashes and current revision pinned; technical and perceptual observations per aspect. | Optional 12s FullHD job SKIPPED, generic A04 FullHD on another story, previews only => target native test NOT RUN. |
| RV-15 P0 · Negative controls | Re-test historical failing A04 repeated abstract 12-scene video and old synthetic 12/30/45/60 preview corpus to ensure matrix detects RV-03/06/07/10 defects even if G1–G9 green. | Known bad content remains explicitly FAIL for G10 while codec still technical PASS; old artifact hashes preserved as RED reference. | Any blanket ALL PASS due to FFmpeg success, no human reviewer or altered baseline => TEST DESIGN FAIL. |
| RV-16 P0 · Corrected export RED→GREEN | After actual coder fix, compare old RED and NEW exact source/MP4 SHA, rerun full scene/video/audio/rights matrix on both native aspects and record every defect closed by timestamp. | Missing/wrong cue, speech and layout issues demonstrably corrected; no regression or waiver of local-qc-2. | Change to fixture text/art alone without new final export/human playback, old-green reused on new canonical, deleted failing tests => BLOCKED. |
| RV-17 P0 · G10 creator decision | Human creator watches/listens full NEW hashed portrait and landscape at 1x, checks facts/voice/motion/layout/source rights; scores five standard dimensions 1–5 and signs identity/device/date. | All five rubric scores **4–5**, zero critical defects, warnings acknowledged, both exact output hashes approved by creator. | Any score 1–2 or critical => REJECT/BLOCKED; score 3 => REVISE; absent scores/human review => PENDING HUMAN REVIEW. Technical PR PASS-CODE does NOT grant G10. |
| RV-18 P1 · Bug communication | Capture exact per-aspect timecode, expectation, actual, reproducible source/fixture vs product context; link issue #101/#102/#103 or new unique issue; BA assigns file owner. | One accountable BA-approved coder per touched path, independent QA owner, retest proof after fix; no duplicate spam. | Vague “video fine/looks bad” without SHA and scene or incorrectly auto-assigning obsolete coder→feature mappings => REVISE/BLOCKED handoff. |

**Duration coverage:** use four 12/30/45/60-second stories where available (each portrait+landscape) **AND** an actual same-project rights-cleared native FullHD final candidate for release. Eight preview files from a fixture do **not** constitute eight native 1080p release tests. Each missing required dimension or missing final source is **NOT RUN**; do not silently substitute unrelated synthetic video.

**Final gate rule:** technical PR may merge after independent tester QA for the **code it changed** while its synthetic artifacts stay HUMAN NOT APPROVED. **Do not release a product video** unless the *creator* approved both exact final-output hashes and reviewed actual native 1x video/audio. A critical G10 failure cannot be averaged away by four other positive scores. Preserve failures and use BA01+BA02 to route actual source owners; testers do not auto-merge their own authored QA changes.
